# GPT 推广消费奖励

用户规则：仅 GPT 商品产生奖励；每笔符合条件的人民币主订单随机一次，整数 1～5 元，转入钱包后可抵扣全站商品，不可提现。数量和子订单不增加抽取次数。奖励不超过符合条件商品净支付金额的整数部分，不足 1 元不产生奖励。

## 配置

后台推广设置选择「GPT 随机消费奖励」模式（`gpt_random_wallet`），填写商品 ID 白名单。后端同时要求商品 slug 以 `gpt-` 或 `chatgpt-` 开头，非 GPT 商品误加入名单也不计奖。本模式不使用旧商品返利开关或百分比。现有确认天数继续生效；本次用户已确定付款满 7 天后可使用；本次合并与发布流程见 `operations/affiliate-wallet-release/README.md`。

`gpt-wallet-rewards.disabled.json` 是关闭状态的配置草案，未导入生产。ID 根据 2026-10-16 公开商品接口读取，发布时必须重新核对，不能跨环境盲目导入。以后新增 GPT 商品需明确加入名单。

## 使用与退款

- 符合条件的付款产生待确认/可用奖励；重复付款通知不重抽、不重复记账。
- 用户点击「转入消费余额」，将成熟奖励一次性转入钱包；重复请求不会重复入账。
- 后端禁止新模式提现和打款；即使之后切回旧模式，`gpt_reward` 记录仍不可提现。
- 保存计奖时的参与商品金额快照；退款按参与商品的金额扣减奖励，不受后来名单修改影响。非 GPT 子订单退款不扣 GPT 奖励；GPT 部分或全部退款按对应金额扣回。已转入奖励同时产生钱包冲正流水。
- 若奖励已消费，退款仍可完成，余额记录欠额；后续充值/奖励先补足欠额。存在欠额时禁止下单与付款，包括取消余额抵扣后直接在线支付；充值入口仍可使用。余额恢复到零才允许购买，只有正余额可抵扣。
- 历史现金佣金、已完成现金打款不自动转换或追偿。
- 欠额出现前的旧支付链接若实际到账，支付保留成功记录及欠额异常标记，款项幂等转入钱包抵欠额，订单不会自动交付；补齐后需重新主动支付。后台按异常提示核对订单与钱包流水。

## 原分支验证与边界（本次发布前）
