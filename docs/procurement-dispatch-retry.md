# 采购队列自动补投

新增每分钟 `procurement:retry_pending` 巡检，只重新投递现有采购单 ID。首次队列失败安排 1 分钟后重试；巡检领取时持久化 5 分钟租约，防并发重复领取，并允许入队响应丢失、Redis 丢失任务或进程中断后恢复。每轮最多 200 条，已领取条目不阻塞后续候选。

只有 pending/failed、submission_version=1、无 submitted_at、无请求/连接摘要且无任何上游回执的订单可领取。候选查询与原子领取均复核资格及本地/父订单状态；取消、退款、旧版本、已提交、结果不确定、已有回执等不重新采购。领取不创建采购单、不清除提交标记，也不直接调用供应商。

消费端继续使用 BeginSubmission 的持久化一次性提交锁与本地订单号幂等键；投递重复不能转化为第二次供应商调用。供应商响应丢失仍保持不确定状态，必须核对回执，不能通过自动重试猜测未扣款。已接受订单继续原 30 分钟交付巡检，不改变为每分钟轮询。

新增隔离测试覆盖首次/持续队列故障、同 ID 恢复、并发领取、任务丢失、16 类提交/回执保护、12 类本地/父订单状态、4 类读取后状态变化，以及 Figma 自动补投至唯一采购/交付。定时任务的消费者注册和错误传播另有回归测试。测试没有真实采购或扣款。

本功能恢复已持久化采购单的队列投递失败，不负责修复建采购单之前的数据库写入失败。自动恢复依赖队列及调度服务恢复运行，不会绕过关闭的队列或支付/退款安全门禁。
