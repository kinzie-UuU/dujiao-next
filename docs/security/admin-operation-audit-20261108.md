# 后台关键业务操作审计

基线：e42f2f733edbec15d03fa016d4cec1071ef96f65。保留采购重试与提交围栏。

新增独立 `admin_operation_audit_logs` 表，由正常启动迁移创建。每条包含管理员 ID/用户名、服务端 request ID、规范化 ClientIP（沿用既有可信代理策略）、动作、目标、结果、时间，以及显式 allowlist 的前后快照。未读取或复制 HTTP 请求/响应正文；不持久化客户内容、邮件正文、口令、API key/secret 或数据库密文。凭证仅记录变化布尔；连接 URL、名称、SMTP 地址等也只记录变化布尔。

覆盖：

- `PATCH /admin/orders/:id`：订单状态前后。
- `POST /admin/payments/:id/manual-confirm`：支付状态、关联订单 ID；不记录付款人/交易凭据。
- 连接创建、更新、状态切换：状态、协议、重试次数、汇率、加价、取整、自动跟价；敏感连接字段仅变化布尔。
- 批量按 ID 导入映射：最多 500 项（超过显式截断）的既有映射存在状态、成功后的映射/本地商品 ID/启用状态；区分全部失败/部分失败。
- 映射启用状态修改。
- 连接重新应用加价：最多 500 个 SKU 的价格/成本前后快照，超过显式 `truncated=true`。原业务服务吞掉单项写错误，因此结果为 `completed_unverified`，`reported_updated_products` 仅为服务报告值，不代表全部持久化成功。
- SMTP：安全配置字段前后，密码/用户名/主机/发件信息只记录变化布尔。
- Google/Telegram 登录配置、验证码：开关或 provider 前后，完整配置只比较并记录 `configuration_changed` 布尔。

成功由业务服务实际返回值显式标记，不从 HTTP 200 推断。请求绑定/鉴权失败仍由既有请求日志负责；进入上述业务调用后的失败记为 `failed`。失败表示调用未成功返回，不承诺业务数据库完全未变更。

保护边界：

- 快照是业务事务外的观察值，可能包含同一对象并发写入；不是事务原子或防篡改账本。快照获取失败显式 `snapshot_available=false`，不阻止原业务操作。
- 写审计失败不回滚或重试已完成交易；发出 `admin_operation_audit_write_failed` 错误日志，只含请求 ID/目标/动作/管理员 ID，避免数据库异常泄露 SQL 内容。
- 当前没有管理端审计查询 UI、自动清理或外部通知；运维可按 request_id/actor/action/target 检索新表。不得把该表称为全部后台操作审计。删除、单商品导入、按分类导入、非本次列明配置、供应商 ping/SMTP 测试等仍不在覆盖内。
- 迁移仅增加新表，不改业务数据。旧版本能忽略新表；上线仍必须独立验证旧→新→旧启动/鉴权、迁移及采购保护。
